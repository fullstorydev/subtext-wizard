## About this install

This is a React Native app, so capture comes from Fullstory's native mobile SDK plus its React Native package. There is no `<script>` snippet and no Content-Security-Policy to change. Ignore any web install instructions in the reference docs.

Use these values. They are specific to this organization; use them exactly as given:

- Org id: `{{ORG_ID}}`
- Server URL: `{{SERVER_URL}}`

The Server URL only needs to be set when it differs from the default `https://fullstory.com`.

Mobile capture requires the Fullstory Mobile add-on on the org. You can't check this from the codebase; just mention it in Step 5.

## Step 1: Pre-check

Determine whether capture is *actually* installed. Stop at the first positive match:

1. `package.json` lists `@fullstory/react-native` in `dependencies` or `devDependencies`.
2. `babel.config.js` lists the `@fullstory/react-native` plugin.
3. Expo config (`app.json`, `app.config.js`, `app.config.ts`) lists the `@fullstory/react-native` plugin.
4. `android/app/build.gradle` (or `.kts`) applies the `fullstory` plugin, or `ios/*/Info.plist` has a `Fullstory` (or `FullStory`) dictionary with an `OrgId`.

Do NOT broad-grep for "fullstory"; it matches copy and comments.

If capture is already installed, report "Subtext capture already installed at {file}" and stop.

Do a read-only pass:

- **Workflow**: decide which one this app uses:

- **SDK version**: look up the latest Fullstory Android/iOS SDK version from the Fullstory release notes (https://help.fullstory.com/hc/en-us/articles/360042772333 and the Android equivalent) and the latest `@fullstory/react-native` on npm. Use the same Android and iOS SDK version.

## Step 4: Install

Reference: https://help.fullstory.com/hc/en-us/articles/360052419133-Getting-Started-with-Fullstory-React-Native-Capture

### 4a. Package and Babel (all workflows)

1. Add `@fullstory/react-native` to `dependencies` with the project's package manager (look at the lockfile: `yarn.lock`, `pnpm-lock.yaml`, `bun.lockb`, or `package-lock.json`; for Expo, `npx expo install @fullstory/react-native` is fine).
2. Add `"@fullstory/react-native"` to the Babel `plugins` array. If there's no Babel config in an Expo project, create `babel.config.js`:

   ```js
   module.exports = function (api) {
     api.cache(true);
     return {
       presets: ['babel-preset-expo'],
       plugins: ['@fullstory/react-native'],
     };
   };
   ```

### 4b. Expo (managed, or prebuild that's regenerated)

Add the config plugin to `app.json` / `app.config.*` under `expo.plugins`. `version` is the Fullstory mobile SDK version you looked up in Step 2:

```json
["@fullstory/react-native", {
  "version": "<FULLSTORY SDK VERSION>",
  "org": "{{ORG_ID}}"{{EXPO_HOST_PROPERTY}}
}]
```

Do NOT edit generated `android/` or `ios/` directories in this workflow. Note for the user: Expo Go can't load native modules, so they'll need a development build (`npx expo run:ios`, `npx expo run:android`, or an EAS dev build).

### 4c. Bare React Native (and Expo projects with hand-maintained native dirs)

**Android** (https://help.fullstory.com/hc/en-us/articles/360040596093):

1. Add the Fullstory Maven repo `https://maven.fullstory.com`. If `android/settings.gradle` has `pluginManagement`/`dependencyResolutionManagement` blocks, add it to both `repositories` lists; otherwise add it to `buildscript.repositories` in `android/build.gradle`.
2. In `android/build.gradle` `buildscript.dependencies`: `classpath 'com.fullstory:gradle-plugin-local:<FULLSTORY SDK VERSION>'`.
3. In `android/app/build.gradle`, apply the plugin (`id 'fullstory'` in `plugins {}`, or `apply plugin: 'fullstory'` after the Android plugin) and configure it:

   ```groovy
   fullstory {
       org '{{ORG_ID}}'{{GRADLE_SERVER_LINE}}
       enabledVariants 'all'
   }
   ```

   `enabledVariants 'all'` lets the user see a captured session from a debug build; the default is release only. Mention in Step 5 that they may want to narrow it later.
4. Translate to Kotlin DSL (`maven("https://maven.fullstory.com")`, `classpath("...")`, `id("fullstory")`, `org = "..."`) if the files are `.kts`.
5. Make sure `AndroidManifest.xml` has the `INTERNET` and `ACCESS_NETWORK_STATE` permissions.

**iOS** (https://help.fullstory.com/hc/en-us/articles/360042772333):

1. Auto-linking pulls in `fullstory_react-native`. If the Podfile doesn't use auto-linking, add `pod 'fullstory_react-native', :path => '../node_modules/@fullstory/react-native'`.
2. Add the Fullstory pod to the app target in `ios/Podfile`:

   ```ruby
   pod 'FullStory', :http => 'https://ios-releases.fullstory.com/fullstory-<FULLSTORY SDK VERSION>-xcframework.tar.gz'
   ```

3. Add a `Fullstory` dictionary to the app's `Info.plist`:

   ```xml
   <key>Fullstory</key>
   <dict>
       <key>OrgId</key>
       <string>{{ORG_ID}}</string>{{PLIST_SERVER_ENTRY}}
   </dict>
   ```

4. Add a Run Script build phase named `Run FullStory Asset Uploader` after the default phases, by editing `project.pbxproj` carefully (or tell the user to add it in Xcode if you can't do it safely):

   ```sh
   "${PODS_ROOT}/FullStory/tools/FullStoryCommandLine" "${CONFIGURATION_BUILD_DIR}/${WRAPPER_NAME}"
   ```

5. Run `pod install` in `ios/` if CocoaPods is available. If it isn't, or it fails, leave the Podfile change in place and tell the user to run it.

Do not attempt a full native build; it takes minutes and needs simulators and signing the user controls.
